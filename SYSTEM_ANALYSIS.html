Sample Trial Request — Complete Workflow Design

Needs Wiring

The SampleTrialRequest model and basic UI exist. Here's the complete flow that needs to be wired:

SUBMITTED

Factory fills form: fabric, brand partner, FUZE tier, volume, ICP lab

→
UNDER_REVIEW

Admin sees it in /admin/sample-trials

→
APPROVED

Admin approves → needs to trigger shipping instructions

→
SAMPLE_SHIPPED

FUZE ships samples to factory → track shipment

→
ICP_PENDING

Factory applies treatment, sends fabric to ICP lab

→
COMPLETE

ICP results submitted → interpretation

What Needs to Happen at Each Status Change

TransitionAuto-ActionsNotifications
→ SUBMITTED Create SampleTrialRequest record. Log in AuditLog. Push notification to all admins. Email admins (sendTrialAdminNotification — already exists).
→ APPROVED Calculate FUZE sample volume needed (from lib/fuze-calc). Log approval. Email factory user: approval confirmation + expected timeline. Push notification to factory user.
→ SAMPLE_SHIPPED Create SampleShipment record. Generate shipping docs. Record tracking number. Email factory: tracking number + estimated delivery + sample handling instructions (storage temp, shelf life). Push notification.
→ ICP_PENDING Auto-create TestRequest PO for ICP testing at selected lab. Generate sample prep instructions for factory (based on treatment method). Email factory: ICP lab address + shipping instructions for treated fabric + required sample size + labeling requirements. Push notification.
→ COMPLETE Link ICP results to trial. Run AI interpretation. Update factory's fuzeEnabled status if results pass. Email factory + brand partner: results summary with FUZE tier. Push notification to all parties.
